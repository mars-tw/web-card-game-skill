## (1) 稀有度材質 CSS 質感層次

### 1.1 四階定義與掛載證據

| 階 | 宣稱材質 | CSS 選擇器 | 實作手法（證據） | 掛載 |
|---|---|---|---|---|
| 普通 | 銀鋼 | `.card.rarity-common` | 內填深灰藍 + `repeating-linear-gradient(105deg,…)` 邊框刷痕 | battle `index.html:179`；pack `index.html:159` |
| 稀有 | 藍晶 | `.card.rarity-rare` | 藍系多停點邊框漸層 + 外光 `0 0 17px rgba(59,130,246,.58)` + 微 inset | battle `180`；pack `160` |
| 史詩 | 紫紋 | `.card.rarity-epic` | `repeating-conic-gradient` 分段紫晶邊框 + 外光 21px | battle `181`；pack `161` |
| 傳說 | 金箔 | `.card.rarity-legendary` | 金多停點邊框 + `background-size:240%` + `legendaryFoil` 位移動畫 | battle `182`、keyframes `568` |
| 傳說 idle | 呼吸光 | `.card.legend-idle` | 併跑 `legendaryFoil` + `legendIdle` 外光 18→50px | battle `184-188`；`RARITY.legendary.idle:true` → `battle.js:1803` |

變數層（`cards.js:15-19`）：

| rarity | glowSize | idle | 用途 |
|---|---|---|---|
| common | 0 | false | 不發光，階梯地板正確 |
| rare | 14 | false | 寫入 `--glow-size`（見下節覆寫問題） |
| epic | 20 | false | 同上 |
| legendary | 28 | true | 供 `legendIdle` 與 summon 衝擊色 |

**階梯可讀性：PASS。** 四階在色相（灰／藍／紫／金）與動勢（靜→靜強光→靜強光→動）上清楚可分，符合「一眼分稀有」的卡牌產品語法。

### 1.2 金箔動畫 — 實作品質

**戰鬥端（常駐對戰卡面）**

```text
border-box 金色 linear-gradient
  → background-size: 100% 100%, 240% 240%
  → animation: legendaryFoil 3.8s linear infinite
  → legend-idle 再疊 box-shadow 呼吸
```

| 優點 | 限制 |
|---|---|
| 零圖資、GPU 友善（位移 `background-position`） | **箔只走在邊框層**，卡心藝術區不參與金屬感 |
| reduced-motion／low-perf 有關（`index.html:592-620`） | 靜止一幀時仍靠漸層停點辨識，但不如「邊框 mask 掃光」利落 |
| 與 `legendIdle` 外光疊加，傳說在場上「會呼吸」 | 多張傳說同場時外光 50px 可能互相漂白（P2） |

**開包端（更高一階）**

| 項目 | 證據 | 品質差 |
|---|---|---|
| `.frame-sheen` + `mask-composite:exclude` | pack `index.html:163-164` | **只照亮邊框環**，不污染卡心；這是真·框掃光 |
| `legendFrameSweep` 3.2s | pack `435` | 與 battle 的 `legendaryFoil` 概念重複但實作更精 |
| `legend-pull` / `legendShine` / `beam` | pack `169`、`177-178`、`438` | 翻開瞬間有爆發，battle 無對等入場箔效 |

**判定：金箔「有動畫、有階梯感」——PASS 功能；「像 AAA 卡包金箔」——未達。**  
實作是 **動畫邊框漸層 + 外光脈衝**，不是全息／噪點箔／法線假反光。對玩法足夠；對宣傳特寫，**開包端的 `frame-sheen` 明顯勝出，且未回灌戰鬥端** → **P1 雙端漂移**。

### 1.3 紫紋（史詩）— 實作品質

| 觀察 | 證據 | 判定 |
|---|---|---|
| 意圖正確：conic 切面像紫晶／紋章 | `repeating-conic-gradient(from 35deg,#e9d5ff 0 7deg,#7e22ce …)` | 設計語言對 |
| 邊框僅 **2px**（battle）／**3px**（pack） | battle `172` vs pack `154` | 薄邊上 conic 高頻分段易糊成「紫邊」，**紋理可讀性不穩** |
| 外光 + inset 補層次 | battle `181` | 遠看靠「紫光」而非「紫紋」辨識 |
| 與陣營 `faction-conclave` 紫紋 art 疊加時 | battle `280` | 史詩 + 結社可能過紫，稀有度／陣營語意重疊（P2） |

**判定：史詩在縮圖／場上以「紫色光暈」勝出，以「紋」字面略弱。** 仍優於僅改 `border-color` 的偷懶作法，但未到「特寫可數切面」的材質級。

### 1.4 藍光（稀有）— 實作品質

| 觀察 | 證據 | 判定 |
|---|---|---|
| 藍晶邊框停點清楚（`#bfdbfe → #2563eb → #60a5fa → #172554`） | battle `180` | **四階裡最乾淨的一步** |
| 外光 17px + 微 inset 藍 | 同左 | 靜態即像「附魔框」，不必靠動畫 |
| 費用寶石同為藍系 | `.card .cost` battle `233-240` | 稀有卡「框藍 + 費藍」和諧；普通卡費仍藍（全稀有度共用 cost 樣式）→ 費用語意≠稀有度，可接受 |
| `--glow-size:14` 被選擇器 **整段 box-shadow 覆寫** | base `174` vs rare `180` | 變數系統對 rare／epic **形同裝飾**（P2 維護） |

**判定：藍光品質最高、最穩，是 r56 材質階梯的「可信中段」。**

### 1.5 立體徽章與陣營戰場色調（r56 附帶主軸）

| 元件 | 證據 | 品質 |
|---|---|---|
| 費用六角寶石 | `clip-path:polygon(…)` + 徑向高光 + 雙 drop-shadow | **強** — 宣傳近拍合格 |
| 攻／血立體章 | 異形圓角 + 徑向寶石 + inset 高光／暗角 | **強** — 與平面 pill 對比鮮明 |

| 嘲諷 `taunt-crest` | battle `259-267`、DOM `battle.js:1826` | 盾形 clip + 內描邊 + 微動畫；**玩法可讀且可上圖** |
| 陣營 art 紋理 | wardens／conclave／wild 各有 pattern；`wintershadow` 僅 CSS 變數 | **三強一弱**（`279` 無專屬 `.art` 規則） |

| 開包懸念 `.suspense` | pack `165-166`；掛載 `pack.js:612` | 剪影 + `?` + `--glow` 外光；**宣傳價值高** |

## (2) 戰場資訊層次（卡牌／血量／法力／log）

### 2.1 版面權重地圖（由高到低）

依面積、對比、動效、位置綜合推估（桌機 shell 心智模型）：

| 權重帶 | 元件 | 視覺手段 | 是否合理 |
|---|---|---|---|
| **L1 決策主體** | 場上／手牌 `.card` | 124×176、稀有度光、選取／可攻／可打 outline | **合理** — 卡牌必須是最重 |
| **L1b 狀態覆蓋** | `.can-attack` 綠、`.selected` 金框、`.targetable` 脈衝 | 常駐／週期 box-shadow | **合理但易蓋過稀有度身份光**（P2） |
| **L2 卡內數值** | `.atk` / `.hp` 寶石 | 高對比、固定角落 | **合理** — 交戰讀數快 |
| **L3 英雄資源** | `.hp-badge` / `.mana-badge` | 實心色 pill、15px 粗體、emoji | **玩法夠用；質感低於 L2** |
| **L3b 氣氛** | 敵場 `--opponent-tone`、body 氛圍光 | 低飽和 radial | **合理** — 敘事不搶戲 |
| **L4 指令** | `.end-turn`、controls sticky | CTA 漸層金、底部黏著 | **合理** |
| **L5 敘事文字** | `#log`、`.target-status` | muted、小字、固定矮高 | **刻意降權 — 正確方向** |
| **L6 次系統** | quest-panel、diff/perf 列 | 半透明面板 | 矮視口時可能上浮干擾（既有 RWD 議題） |

### 2.2 分項審

#### 卡牌（權重）

- 正確佔據垂直中段雙戰場（`#enemyField` / `#playerField`，`index.html:793-794`）。
- 稀有度外光讓「強卡」在靜態陣型中更跳 — **有利宣傳也有利掃場**。
- 風險：多張 rare+ 同場 + `can-attack` 綠環 → **身份色與狀態色搶同一視覺通道**（外光／描邊）。玩法優先狀態沒問題，但會讓「四階材質」在熱戰中變難讀（P2）。

#### 血量（英雄 vs 隨從）

| 層 | 樣式 | 問題 |
|---|---|---|
| 隨從 `.card .hp` | 立體血滴寶石 | 與攻對稱，讀數清楚 |
| 英雄 `.hp-badge` | `background: var(--hp)` 實心紅 pill | **無高光、無邊、無危險態樣式**（隨從有 `.hurt`，英雄 badge 無對等） |

英雄血量在規則上是「終局資源」，資訊優先級應 ≥ 單隻隨從血，但 **視覺工藝反而低於隨從章**。  
玩法掃視仍靠色塊 + 數字夠用；**宣傳截圖若取「英雄列 + 場」構圖，扁平 pill 會瞬間暴露原型感** → **P1（觀感）**。

敵我英雄列對稱（`786-804`），敵方只顯示 HP、我方 HP+法力 — 符合「玩家操作資源在己側」習慣，**層次可接受**。

#### 法力

- 僅玩家側 `mana-badge`（藍實心 pill），與 HP 同型不同色 — **配對清楚**。
- 與卡面費用寶石（立體、clip-path）**語言不一致**：同一「法力」概念，手牌角是寶石、頂欄是 emoji pill。
- 無「費用剛好／不夠」的 badge 狀態樣式（靠手牌 `.playable` / `.disabled` 承擔）— 玩法 OK，頂欄法力不會搶卡。

**判定：法力權重正確偏低於場上交戰；工藝與卡面未對齊。**

#### Log

| 項目 | 證據 | 判定 |
|---|---|---|
| 高度 52px（桌機）→ 矮視口 40／32／24px | `380-381`、`628`、`641`、`658` | 極矮時近乎「一行摘要」 |
| 色 `var(--muted)`；`.me` 藍／`.ai` 紅 | `380-382` | 敵我可分，整體仍淡 |
| 位置：英雄列與手牌之間 | `806-807` | 像字幕帶，不擋場 |
| `aria-live="polite"` | `807` | 無障礙 OK |

**判定：log 降權正確，不應與卡牌爭 L1。**  
缺點是戰報「幾乎不存在於視覺記憶」——連殺、斬殺等高潮若只靠 log 無補強，會更依賴浮動 dmg／spell-flash（後者有 `559-562`）。這是產品取捨，非 bug。

### 2.3 權重分配總評

| 問題 | 嚴重度 |
|---|---|
| 卡牌 > 狀態光 > 卡內數值 > 英雄資源 > log 的排序 **大方向正確** | — |

## (3) 宣傳截圖標準：3 個最划算下一步

「宣傳截圖標準」= 單幀靜止仍好看、稀有度可讀、無水平溢出、主體（卡／英雄）有商品級材質、不靠長動效才能成立。

| 順位 | 下一步 | 為何划算 | 預估成本 | 預期收益 |
|---|---|---|---|---|
| **1** | **把 pack 的傳說 `.frame-sheen`（mask 邊框掃光）回灌 battle，並讓 rare／epic 靜止幀邊框在 2px 下仍可讀** | 一次 CSS 對齊消滅「開包金、對戰鐵」雙端落差；靜止截圖不依賴 3.8s 循環也能看出傳說 | 小（搬選擇器 + 戰鬥卡 DOM 加一層 `frame-sheen`，對齊 `pack.js:624`） | **最高** — 場上傳說特寫立刻接近開包品質 |
| **2** | **英雄 `.hp-badge`／`.mana-badge` 改為與 cost／atk／hp 同一套寶石語言**（徑向高光、inset、細描邊；可選低血脈衝） | 每個對戰截圖都有英雄列；現在扁平 pill 是整圖的最大「原型洩漏」 | 小（純 CSS，不動規則） | **高** — 全畫面完成度拉齊，不必新美術 |
| **3** | **閃卡 foil 升為多停點色散（微虹彩）+ 固定一組「可重現的展示盤」**（例如：懸念剪影一幀、傳說+嘲諷盾、三對手色場各一） | foil 現況是單色白斜掃（battle `219-222`／pack `203-205`），特寫像塑膠膜；懸念 `.suspense` 已是現成海報語言卻未產品化截圖流程 | 小～中（CSS 漸層 1 日內；展示盤可用現有 e2e／`__test` 狀態或手冊步驟，不必新系統） | **高／穩** — 社群圖「開包瞬間」與「閃卡收藏」兩條素材管線 |

### 3.1 刻意不排進前三（但有效）

| 項目 | 原因 |
|---|---|
| 重畫卡圖／引入外部 UI pack | 成本高；r56 已選純 CSS 路線且合理 |
| wintershadow 專屬 art 紋理 | 該做，但只補 1／4 陣營，對「預設哈爾登藍場」主視覺截圖邊際較低 → 可作 P2 順手 |
| 加厚 log 或戰報 HUD | 與目前正確的降權策略衝突；宣傳靠 FX／卡面即可 |
| 新粒子／更重全屏光 | 截圖用靜幀；且 reduced-motion 會關掉 |

### 3.2 截圖驗收建議（給下一輪實作，非本輪改碼）

| 鏡頭 | 應看見 | 不合格訊號 |
|---|---|---|
| 四階並排（手牌或收藏） | 銀／藍／紫／金邊一目了然 | 史詩=紫實線、傳說靜止像普通金邊 |
| 傳說場上特寫 | 框環掃光或清晰金箔停點 + 不炸版 | 只有黃光暈、邊框無金屬層次 |
| 英雄列 + 雙場 | HP／法力不顯「HTML 預設 button」 | 實心扁 pill 與立體卡章同框違和 |
| 開包懸念 | 黑影 + `?` + 稀有色暈 | 灰塊無 glow、或五張同時無層次 |
| 三對手色場 | 藍／紫／橙可辨且卡面仍主體 | 色罩過重蓋住稀有度 |
